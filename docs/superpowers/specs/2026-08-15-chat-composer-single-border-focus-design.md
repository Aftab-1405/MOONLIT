# Chat Composer Single-Border Focus Design

## Problem

The chat composer renders two simultaneous focus boundaries: its existing 1px border changes to the focus color while a separate 2px outline is added with a 2px offset. This produces the same double-border effect previously corrected on outlined Auth inputs. The interaction audit currently encodes the faulty two-layer behavior.

## Scope

- Correct the focus state generated by `getComposerSurfaceSx` and consumed by `ChatInput.jsx`.
- Update the interaction audit so it rejects any composer outline or shadow during focus.
- Preserve composer dimensions, radius, background, overflow behavior, toolbar layout, input behavior, and all child-control focus indicators.
- Do not restructure `ChatInput.jsx` or change non-composer controls.

## Approved Design

- The idle composer uses one 1px border with `theme.palette.border.idle`.
- The focused composer uses one 2px border with `theme.palette.border.focus`.
- The focused composer uses no outline and no box shadow.
- Focus continues to be communicated with a high-contrast border and does not depend on color alone because its thickness also changes.

## Implementation

1. Add a failing interaction-audit assertion for a 2px focus border with no outline or shadow.
2. Change `getComposerSurfaceSx` to set `borderWidth: 2` in `&:focus-within` and remove `outline` and `outlineOffset`.
3. Verify computed browser styles on the focused composer and run the frontend regression suite.

## Success Criteria

- Browser inspection reports exactly one visible boundary layer on the focused composer.
- The focused border is 2px and uses the focus token.
- The idle border remains 1px.
- Interaction audit, tests, lint, and production build pass.
